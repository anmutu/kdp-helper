# 导出历史与可编辑项目备份

日期：2026-09-20。延续已确认的个人本机工具范围，不加入账号、云同步或自动出版。

## 设计边界

- 导出历史以磁盘上已完成的版本目录为准，兼容已有导出；显示草稿/正式、仅内页/完整、时间、页数和是否对应当前快照。临时目录不展示，损坏版本单独提示，不影响健康版本。
- 备份采用带版本号和 SHA-256 校验清单的 ZIP，而不是仅导出项目 JSON。包含当前项目、全部仍被项目引用的候选和参考图、已完成的历史 PDF/说明/快照；不包含 API Key、服务配置、生成任务或幂等操作记录。
- 采用不压缩 ZIP 条目：PNG 和 PDF 本来已压缩，避免再次压缩带来的 CPU 开销及解压炸弹。只接受本工具生成的格式，不接受重新压缩的 ZIP 或任意目录归档。
- 一次备份/恢复上限 256 MiB、4096 个文件；单个文件上限 128 MiB，JSON 上限 16 MiB。超限明确停止并提示手工备份目录，不静默漏掉素材或历史版本。
- 恢复总是新建副本，重新分配项目、页面和素材 ID；保留文案、画风、来源与裁切，但撤销出版规格及选图确认。历史文件仍为旧快照，不能被误认为恢复后已重新审核的文件。
- 上传流、ZIP 条目路径、数量、尺寸、清单、校验和、图片解码与引用归属均需检查。所有输入验证完成后写暂存区，项目文件最后发布；失败清理本次创建的文件，不覆盖原项目或配置。
- 用户界面沿用现有工作台：导出步骤展示历史；侧栏新增备份与恢复对话框，无需重设计整套界面。

## 实施与验证

1. 用临时目录补导出历史与备份往返、恶意输入、失败清理测试，先确认失败。
2. 新增独立的历史查询与备份服务，复用现有存储锁与 API 边界，不把归档处理塞进界面。
3. 接入本机下载/恢复接口与工作台；备份前保存当前修改，恢复前提示创建副本。
4. 执行全量测试、类型检查、lint 与生产构建；不调用付费模型、不上传 KDP，不将未执行的浏览器或印刷验收标为通过。

文件计划：`src/domain/project-files.ts` 管格式与共享类型；`src/server/exports.ts` 管历史；`src/server/backup.ts` 管备份格式及事务；`src/app/api/` 为薄接口；工作台新增历史与备份组件；`tests/exports.test.ts`、`tests/backup.test.ts` 及离线路由测试覆盖实际文件路径。
