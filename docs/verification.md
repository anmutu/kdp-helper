# 第一版实现与验证记录

日期：2026-09-16。范围：本机个人工具，不包含自动 KDP 发布。已写代码并完成以下离线验证，但不把未执行的真实服务调用或浏览器操作算作通过。

## 已实现的闭环

- 四阶段工作台：规格与内容、生成与选图、排版与封面、检查与导出；另有本地模型设置。
- 官方规则作为纯函数与静态预设维护，附来源和核对日期。三种开本的最小/最大页数按各自彩色组合处理；白纸、高级/标准彩色和出血方式明确选择。
- 规格未确认时不调用生成；正式生成前检查请求像素与整本页数，低清试画需要明确选择。
- 每张实际结果保存后再检查像素。不满足印刷要求时保留候选、暂停后续付费请求，不再把整个低清批次继续跑完。
- 批量请求逐张执行，暂停不覆盖成运行状态；重启后在途结果标为未知，不自动重复收费调用。
- 客户端操作 ID 与本地持久化记录配合，重复提交同一次操作不会创建第二个生成任务；未知结果与主动再次生成区分处理。
- 页面、候选、参考图和导出保存在本机。串行自动保存、服务端乐观锁和冲突草稿保留避免静默覆盖。
- 接入兼容接口、参考图编辑入口、可选文字草稿；没有 Key 也可手动编写、导入图片、排版和导出。
- 输出真实内页和完整封面 PDF；也可在封面未完成时单独导出已合格内页。奇数页、低 DPI、缺图、未确认选图、占位文字、文字溢出及缺字阻止对应正式导出。
- 图片扁平化并转为 CMYK，内嵌允许再分发的 Noto 中文字体；PDF 不包含预览辅助线，草稿有明确标记。

## 此次检查发现并修复的重点

1. **字体不能只看“已嵌入”标记。** 初版使用 pdf-lib/fontkit 对 Noto CFF 字体做子集，文件能够保存和解析页数，但独立渲染器报字体异常。最小复现定位到 CFF 嵌入兼容性；现在嵌入经过验证的完整原始 CFF 字体程序，使用对应 CID 字典，并补充独立字体检查回归。实现封装在 `src/server/pdf-font.ts`，仅适用于当前捆绑字体；替换字体或升级相关依赖后必须重新执行字体/渲染回归。此方案增加文件大小，换取可靠嵌入。
2. **避免低清结果继续浪费额度。** 请求尺寸与实际返回尺寸分别检查；非试画返回低清、无法取回结果或服务异常后暂停后续请求。
3. **避免提交重放收费。** 操作标识在发起异步工作前持久化，完成后重放仍返回原任务；相同标识不能绑定不同请求。
4. **暂停和恢复覆盖边界。** 参考图读取期间暂停、暂停但请求在途时重启、排队期间版式改变均有回归用例。
5. **内页与封面可分别完成。** 仅内页导出不再被未完成封面阻止，但明确声明并非整本文件已齐。

## 尚未验证，不能宣称已通过

## 首版有意收窄的地方

- 只覆盖三种经过核对的彩色平装开本、白纸，不是 KDP 全部规格；不支持精装和 Kindle。
- 生成运行时暂时锁定书本编辑，防止并发保存覆盖新候选；可以看任务并暂停。不是实时协同编辑器。
- 采用固定版式与固定正文颜色，提供字号、文字、模板及图片裁切；不提供通用图层/字体/颜色设计器。
- 屏幕使用相同字体和主要几何参数，但仍为近似预览；正式确认以导出的实际 PDF 为准。不提供 PDF/X 认证或屏幕到印刷完全一致的色彩保证。
- 当前 Key 存于权限为当前用户读写的本地文件，不是操作系统钥匙串加密；仅供可信本机使用。备份作品时不要分享 `settings.json`。
- 规则数据不会悄悄在线变化；Amazon 更新规则后，需要维护者核对、更新规则和测试，并在开始新的批量生成前重新核对规格。

本轮没有提交 Git、购买会员、消耗真实生图额度或执行出版操作。
