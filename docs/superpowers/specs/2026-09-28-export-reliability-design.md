# 导出与下载可靠性加固设计

## 目标

在不改变绘本生成、KDP 规格校验和现有用户流程的前提下，减少导出失败后的磁盘残留，并让历史导出文件下载遵循与备份读取一致的文件安全边界。

## 范围

- `exportBook()` 创建临时导出目录后，无论写入或最终改名在哪一步失败，都尝试清理该临时目录。
- 导出文件下载路由复用有界文件读取逻辑，拒绝目录、符号链接和超过安全上限的文件。
- 为上述失败路径补充回归测试，保留现有成功下载和导出行为。

## 不在范围内

- 不修改图片生成、Provider、KDP 规格、PDF 内容或备份格式。
- 不改变历史快照中旧素材的产品策略。
- 不调用真实 coderplan-ai、真实 API Key 或 KDP。

## 数据流与错误处理

导出仍按“渲染 → 写入隐藏临时目录 → 原子改名 → 返回版本信息”的顺序执行。写入阶段或改名失败时，清理隐藏临时目录；清理失败不覆盖原始导出错误。成功改名后不再清理目标目录。

下载路由先确认项目存在，再从受校验的版本目录读取允许的文件名。读取使用 `lstat` 和统一大小限制，文件类型或大小不合法时返回已有的应用错误响应，不将异常细节暴露给客户端。

## 测试策略

- 通过受控文件系统失败场景验证导出临时目录不会残留。
- 验证导出路由可下载合法文件。
- 验证目录伪装、符号链接和超大文件不会被读取。
- 完成定向测试后运行全量测试、类型检查、lint、构建和 `git diff --check`。
