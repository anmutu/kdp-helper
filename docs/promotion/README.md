# 推广文案包与发布策略

为开源发布（github.com/anmutu/kdp-helper）准备的成套文案。所有草稿都遵守一条底线：**只说真实存在的事**——功能以代码为准、数字以测试与官方核对记录为准、不夸大、不暗示与 Amazon 有任何关系。发帖前请再通读一遍，删掉与当时状态不符的句子。

## 渠道与优先级

| 顺序 | 渠道                             | 文件           | 要点                                                                         |
| ---- | -------------------------------- | -------------- | ---------------------------------------------------------------------------- |
| 1    | Hacker News（Show HN）           | `show-hn.md`   | 周二至周四、美东上午发；标题定式 "Show HN: …"；正文克制、多谈取舍            |
| 2    | Reddit r/selfpublish             | `reddit-en.md` | **发前必读当周版规**：自推广可能只允许出现在周六 Check-in 线程，两条稿都备了 |
| 3    | X / Twitter                      | `social-en.md` | 推文串，第一条就要有钩子；附仓库截图更好                                     |
| 4    | 中文平台（即刻 / 小红书 / V2EX） | `social-zh.md` | V2EX 发"分享创造"节点，技术向；即刻小红书面向独立作者                        |

## 节奏与纪律

- 一次只发一个平台，间隔至少 2–3 天，观察反馈再发下一个；不要同一天全渠道群发同一文案。
- Reddit 反垃圾严格：发帖前几天先在该社区正常回帖；主帖发出后**认真回复每一条评论**（前 2 小时在线最重要）。
- 不私信拉人、不在别人的帖子里贴链接刷屏。有人问到相关工具时，先答问题、附一句"我正好开源了一个做这个的"即可。
- 每次发帖后在 GitHub → Insights → Traffic 记录 referrers/clones，知道哪个渠道真的带来用户，下一个平台据此调整文案。

## 回应负面评论的口径（诚实原则）

- **"AI 生图的垃圾"**：工具从不自动生成任何东西——每页由作者挑选并确认；也支持完全不配 API Key、纯导入自己画的图。重点在印刷规格与文件校验。
- **"UI 是中文的怎么用"**：如实承认 UI 目前中文优先，README 有英文说明，国际化在路线图上，欢迎 PR。不要说"很快就有"除非真的排期了。
- **"跟 Amazon 什么关系"**：毫无关系，第三方开源工具；所有规则来自官方公开文档并标注核对日期，印刷前请自行复核。

## 发帖前检查单

- [ ] 仓库 README 徽章是绿的（CI 通过）
- [ ] 发的链接直接落到仓库首页
- [ ] 文案里的功能描述与当前版本一致（尤其新功能）
- [ ] 账号在该平台有正常历史（新号发链接容易被自动过滤）
