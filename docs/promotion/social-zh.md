# 中文平台草稿（即刻 / 小红书 / V2EX）

## 即刻 / 小红书（独立作者向）

**标题备选：**

- 我给自己写了个"做绘本的印刷工作台"，开源了
- 做 KDP 绘本总在尺寸上翻车？我把规格检查做成了免费工具

**正文：**

在做我的第一本 KDP 绘本（26 页黑白）。踩的坑都很蠢：选了标准彩色才发现最少要 72 页、看着清楚的图印出来只有 120 DPI、书脊宽度用错了系数——规则全是公开的，但散在 KDP 四个帮助页里。

于是写了个本地小工具给自己用，今天开源了（MIT，免费）：github.com/anmutu/kdp-helper

它是"规格先行"的：开本、墨水（黑白白纸/米色纸、标准彩、高级彩）、出血先定下来，页数范围、书脊宽度、装订边、每张图最少要多少像素直接算给你，每个数字都标着官方来源和我核对的日期。

然后是完整流程：写页面 → 生成或导入插画（可以完全不配 Key，用自己的图）→ 候选并排对比挑选 → 排版 → 导出校验过的内页 PDF 和完整展开封面 PDF。奇数页、文字溢出、缺字、低清图都会拦下正式导出。

对钱包也狠：请求的像素不够印刷就不发起付费调用；一张低清图回来整批暂停；结果不明的请求绝不自动重试。还带美区印刷成本和版税试算——定价 $9.98 和 $9.99 的版税率是 50% 和 60%，就差 1 美分。

全部数据在本机，没有账号没有云同步。MIT 开源，欢迎自取。

## V2EX（分享创造节点，技术向）

**标题：** 开源了一个 KDP 绘本制作工具：把印刷规格做成带来源的纯函数模块

**正文：**

做 KDP 自出版绘本时最容易翻车的不是画图，是规格：页数范围跟墨水/纸张/开本组合有关、书脊宽度每个组合系数不同、出血只加在上下和外侧、图在最终尺寸下要真 300 DPI……这些规则散在 KDP 四个帮助页。

开源了我的解决方案（Next.js + 本地文件存储，MIT）：github.com/anmutu/kdp-helper

架构上的核心决定：**规格层是一个纯 TypeScript 模块**（src/domain/print-spec.ts），每个数字都带官方来源 URL 和核对日期，配套 115 项测试。前后端共用这层，屏幕预览、服务端校验、导出全走同一套计算。规则变了改模块和测试，运行时零猜测。

几个技术点：

- pdf-lib 嵌 CJK 字体的坑：fontkit 子集化后的 CFF 在独立渲染器下会坏，最后是手工把 FontFile2 替换成 CIDFontType0C 流（src/server/pdf-font.ts），完整字体嵌入，pdffonts 验证通过
- 费用安全：生图调用前先按版式验请求像素，不足直接拒绝；结果按实际返回像素复查，低清即暂停整批；不确定是否计费的请求（超时/断连）永不自动重试，靠持久化操作号防重复提交
- 导出用真实文件校验（页数、页面尺寸、字体嵌入），不是看网页截图
- 从 monorepo 用 git subtree split 剥离历史发布成独立仓库，保留了全部带署名的提交记录

UI 目前中文优先，英文 README 有完整说明。欢迎交流。
